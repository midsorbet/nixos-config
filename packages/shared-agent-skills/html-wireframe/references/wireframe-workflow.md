# Wireframe workflow

Use this reference only when the layout is unsettled or behavior must be reviewed.

Identify the user and job, bounded screen or flow, required information and actions, safe assumptions, and the structural question the artifact should answer.

## Compare directions

When comparison will help, create two or three meaningfully different structures. Vary decisions such as navigation model, grouping and order, primary-action placement, content density, overview versus step-by-step flow, or desktop-to-mobile reflow. Color changes and minor card rearrangements are not separate directions.

Name each direction and state its tradeoff. Keep the same core content and task across directions. Put them in one file when practical, with a small keyboard-operable selector.

## Useful behavior

Use immediate, plain click-through behavior only where it tests navigation, disclosure, or a short flow. Make links, tabs, and next/back actions work when they are part of the review. Do not add elaborate animation, persistence, simulated APIs, or production state management.

Use labeled placeholders for images or rich media unless the asset changes a structural decision. Add annotations only to expose an assumption, open question, or behavior that cannot be shown directly. Low fidelity does not excuse careless spacing, illegible type, or broken responsive behavior.
