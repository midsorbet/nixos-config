# Ideonomy practice

## Construct and evaluate an organon

Start from concrete instances or properties. Give dimensions meaningful values and apply the selected operators so the transformation remains inspectable: identify the changed property, structural relationship, or pair of inputs. For a cross-product, show the input sets and whether every output is represented. Distinguish A-of-B from B-of-A when order changes meaning.

Include an unfamiliar but relevant direction. If a selected method cannot illuminate the subject, state the mismatch and replace it deliberately rather than inventing relevance or repeatedly drawing until something comfortable appears. Merge variants that rely on the same mechanism. Retain a failed transformation when it exposes a dependency.

An empty cell can mean unknown, unexamined, incompatible under stated assumptions, or worth investigating; absence alone predicts nothing. For cross-domain transfers, identify the preserved relationship and where the analogy breaks. Select promising directions for the user's purpose, explain the tradeoff, and give a disconfirming observation, small experiment, or concrete comparison for the strongest practical candidates. For art or fiction, use a scene, audience response, or aesthetic constraint rather than forcing a scientific test. Stop when the requested scope is met or another pass would only rename existing ideas.

## Ground current-state claims

When a candidate says that an inspectable subject already contains or lacks something:

1. Name the exact current-state claim.
2. Search relevant source, schemas, documentation, or behavior for likely names and equivalent concepts, then inspect the surrounding implementation.
3. Match the conclusion to that evidence. Identify an existing capability when found. When it is not found, state the inspected scope and remaining uncertainty; zero keyword matches do not prove absence.

Attach a concise evidence note to the claim. Distinguish “not found in the inspected files” from “does not exist.” This requirement checks descriptions of the subject; it does not prevent hypothetical alternatives or require resolving every speculative idea.

## Picker and continuity

The picker supports `--less`, `--more`, `--print`, and `--seed N`. A seed replays selection only for an unchanged catalog and the same Bash/awk implementation; it does not reproduce a model response. Draws can repeat. The picker is local and needs no network or external service.

Default runs do not write files. `--cooldown-dir /path/to/workspace/state` opts into recency state outside the installed skill. Seeded runs ignore cooldown and do not update it. Cooldown tracks method use, not quality or learning.

On follow-ups, examine an identified gap in the existing organon before drawing again. Preserve useful combinations or reproducible experiments in the user's work only when requested. Editing the installed skill is a separate maintenance task, never a silent consequence of exploration.
